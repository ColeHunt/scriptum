# deploy/digitalocean/

Infrastructure for fleet mode — see
[Worker Fleet](../../docs/deploying/fleet.md) for the operator guide and
[decision 048](../../docs/decisions/048-head-worker-fleet-deployment.md) for
the design.

The **head** is Scriptum's control plane, running as a service in the shared
MARS/WARS `apps-infra` stack. It also serves student files over NFS.
**Workers** are droplets the head creates on demand in the same VPC to run
students' workspace containers, and destroys when idle.

- `terraform/` — the static, one-time resources: the worker firewall (only
  the head's private IP may connect; applied by the `scriptum-worker` tag, so
  it covers every worker the head creates) and the data Volume attached to
  the head. Workers themselves are created at runtime by the head
  (`apps/control/src/fleet/`), not by Terraform.
- `setup-head-nfs.sh` — run once on the head: mounts the Volume at
  `/mnt/scriptum-data` and exports `/mnt/scriptum-data/users` over NFSv4,
  bound to the head's private IP.
- `bake-golden-image.sh` — builds the worker snapshot: Docker, the NFS
  client, and the workspace image pre-pulled.
- `head-ssh.conf` — the head's SSH client settings for reaching workers.

Worker first-boot (mount the export, signal ready) is generated by
`apps/control/src/fleet/worker-user-data.ts`.
